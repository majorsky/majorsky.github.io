VIEWS И URL В DJANGO: МАРШРУТИЗАЦИЯ

Как Django обрабатывает запрос

Цепочка простая: браузер запрашивает адрес, Django ищет его в urls.py сверху вниз, вызывает найденное представление, а то возвращает ответ — HTML, редирект или JSON. Если совпадения нет, отдаётся 404.

Первое представление

Создайте файл blog/views.py и добавьте функцию. Представление — это обычная функция Python, которая принимает запрос:

from django.http import HttpResponse

def index(request):
    return HttpResponse("Привет, мир")

Маршрут

Теперь свяжите функцию с адресом в config/urls.py:

from django.urls import path
from blog import views

urlpatterns = [
    path("", views.index, name="index"),
    path("post/<slug:slug>/", views.post_detail, name="post_detail"),
]

Конвертеры в угловых скобках задают тип и имя параметра: str, int, slug, uuid, path. Значение приходит в функцию вторым аргументом.

name — это не украшение. По имени строятся ссылки в шаблонах, и при смене адреса их не придётся править вручную: {% url "post_detail" slug=post.slug %}.

Приложения и include

Держать все маршруты в одном файле быстро надоедает. В приложении создаётся свой blog/urls.py, а в корневом он подключается:

from django.urls import include, path

urlpatterns = [
    path("blog/", include("blog.urls")),
]

В приложении задайте app_name = "blog" — тогда имена станут с пространством: blog:post_detail. Это спасает, когда в проекте два приложения с одинаковым index.

Шаблоны и контекст

Вместо строки обычно возвращают render — он подставляет данные в HTML:

from django.shortcuts import render, get_object_or_404
from .models import Post

def post_detail(request, slug):
    post = get_object_or_404(Post, slug=slug)
    return render(request, "blog/post.html", {"post": post})

get_object_or_404 — короткая запись «найти или отдать 404». Без неё get бросит исключение и посетитель увидит 500.

В шаблоне данные выводятся двойными скобками, теги — фигурными со знаком процента: {{ post.title }}, {% for post in posts %}, {% if post.is_published %}. Наследование через {% extends "base.html" %} избавляет от копирования шапки и подвала.

Типичные ошибки

NoReverseMatch. Имя маршрута в {% url %} не совпадает с name или не передан обязательный параметр. Проверьте пространство имён: blog:post_detail вместо post_detail.

404 вместо страницы. Часто дело в слэше в конце: path("post/") совпадёт с /post/, но не с /post. Django умеет добавлять слэш автоматически, если включён APPEND_SLASH.

Вся логика во view. Функция на 300 строк с запросами, письмами и расчётами не тестируется. Выносите в сервисные функции и методы моделей.

Сырой HTML в коде. Строки с разметкой внутри представления невозможно поддерживать. Шаблон для этого и нужен.
