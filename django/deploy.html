ДЕПЛОЙ DJANGO НА VPS ПО ШАГАМ

Что понадобится

VPS на Ubuntu 22.04 или 24.04, минимум 2 ГБ памяти, домен и полчаса времени. Схема классическая: Nginx принимает запросы снаружи, Gunicorn запускает Django, PostgreSQL хранит данные, systemd следит, чтобы процессы не падали.

Шаг 1. Подготовить сервер

adduser deploy
usermod -aG sudo deploy
ufw allow OpenSSH
ufw allow "Nginx Full"
ufw enable

Работать под root постоянно не стоит: одна опечатка в команде обходится дорого.

Шаг 2. Установить пакеты

sudo apt update
sudo apt install python3-venv python3-pip postgresql nginx

Затем создайте базу и пользователя PostgreSQL:

sudo -u postgres createuser --interactive
sudo -u postgres createdb blogdb

Шаг 3. Код и окружение

cd /var/www
git clone git@github.com:user/blog.git
cd blog
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

В requirements.txt обязательно фиксируйте версии: django==5.0.6, gunicorn==22.0.0, psycopg2-binary, whitenoise.

Шаг 4. Настройки для продакшна

Три вещи, без которых деплой опасен: DEBUG = False, реальный домен в ALLOWED_HOSTS и секретный ключ из переменной окружения, а не из репозитория.

DEBUG = False
ALLOWED_HOSTS = ["majorsky.ru", "www.majorsky.ru"]
SECRET_KEY = os.environ["DJANGO_SECRET_KEY"]

Файл .env с ключами не коммитится, права на него — только у владельца.

Шаг 5. Gunicorn и systemd

gunicorn config.wsgi:application --bind 127.0.0.1:8000 --workers 3

Три воркера — правило «два ядра плюс один». Чтобы процесс перезапускался после падения и ребута, создайте юнит /etc/systemd/system/blog.service с WorkingDirectory, ExecStart и Restart=always, затем:

sudo systemctl enable --now blog
sudo systemctl status blog

Шаг 6. Nginx

Nginx отдаёт статику и проксирует остальное на Gunicorn. В конфиге сайта важны два блока:

location /static/ {
    alias /var/www/blog/static/;
}
location / {
    proxy_pass http://127.0.0.1:8000;
}

Перед первым запуском соберите статику: python manage.py collectstatic. Если статику раздаёт сам Django через WhiteNoise, блок /static/ можно не писать — но для больших проектов Nginx быстрее.

Шаг 7. HTTPS

sudo apt install certbot python3-certbot-nginx
sudo certbot --nginx -d majorsky.ru -d www.majorsky.ru

Certbot сам пропишет сертификат и настроит редирект с HTTP. Продление — автоматическое, проверяется таймером systemd.

Чек-лист перед запуском

  • DEBUG = False, ALLOWED_HOSTS заполнен, секреты вне репозитория.
  • Миграции применены: migrate, суперпользователь создан.
  • Статика собрана и отдаётся, в консоли браузера нет 404.
  • Настроены резервные копии базы, хотя бы ежедневные.
  • Включён файрвол, закрыт доступ к PostgreSQL снаружи.

Частые ошибки

502 Bad Gateway. Gunicorn не запущен или слушает другой порт. Смотрите journalctl -u blog -n 50.

DisallowedHost. Домен не добавлен в ALLOWED_HOSTS — Django блокирует запрос специально.

Стили не грузятся. Забыли collectstatic либо путь в alias не совпадает с STATIC_ROOT.

Сайт работает, но падает через сутки. Обычно заканчивается память: проверьте число воркеров и размер базы.
